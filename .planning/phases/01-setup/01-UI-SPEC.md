## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn gate not applicable — shadcn/ui is a React + Radix + Tailwind tool; the project's app stack is fixed by `.claude/CLAUDE.md` as Vue 3 + Web Awesome, which shadcn cannot target regardless of Vite being present) |
| Preset | not applicable |
| Component library | Web Awesome (`@awesome.me/webawesome`) — framework-agnostic custom elements (successor to Shoelace), not Radix/base-ui |
| Icon library | `<wa-icon>` default library — ~2,000 free icons courtesy of Font Awesome, resolved from the Font Awesome CDN by default. **Decision for this phase:** self-host the icon set via `setIconPath()` instead of the default CDN resolver, so the app has no runtime third-party network dependency (consistent with "inoffizielles Projekt" on GitHub Pages, no backend, and avoids a CSP/offline surprise). Executor downloads the icon sprite/SVGs into `app/public/icons/` and calls `setIconPath('/icons')` once at app bootstrap. |
| Font | System font stack (Web Awesome default): `ui-sans-serif, system-ui, sans-serif` for body and headings, `ui-monospace, monospace` for code. No custom web font is loaded — this keeps Phase 1 free of font-loading/FOUT concerns and is reused by all later phases unless a phase overrides it. Numeric table/figure cells additionally get `font-variant-numeric: tabular-nums` so digit columns align (see Typography). |

## Spacing Scale

Web Awesome ships its own 4px-rooted spacing scale via `--wa-space-*` custom properties; this phase adopts those tokens directly (as `var(--wa-space-*)`) rather than introducing a parallel scale, since every WA component's internal padding already uses them.

| Token | Value | WA variable | Usage |
|-------|-------|--------------|-------|
| xs | 4px | `--wa-space-2xs` | Icon-to-label gaps, inline chip padding |
| sm | 8px | `--wa-space-xs` | Compact element spacing (e.g. between a `<wa-icon>` and adjacent text) |
| md | 16px | `--wa-space-m` | Default element spacing, `ChartCard` internal padding |
| lg | 24px | `--wa-space-l` | Section padding, gaps between stacked `ChartCard`s |
| xl | 32px | `--wa-space-xl` | Layout gaps between major page regions |
| 2xl | 48px | `--wa-space-3xl` | Major section breaks (e.g. between `PageIntro` and first content block) |
| 3xl | 64px | `--wa-space-4xl` | Page-level top/bottom spacing on wide viewports |

Exceptions:
- `2px` (`--wa-space-3xs`) — hairline gaps inside WA components only (e.g. `<wa-divider>` thickness); never used for layout spacing directly by project code.
- `12px` (`--wa-space-s`) and `40px` (`--wa-space-2xl`) exist in the WA scale and may appear inside WA component internals (e.g. form-control padding); project layout code should prefer the 7 named tokens above and not reach for these two directly.
- `80px` (`--wa-space-5xl`) is available for large page-level breaks on wide viewports if a later phase needs it; not used in Phase 1.
- `44px` minimum touch target for icon-only interactive elements (nav toggle, "Quelle anzeigen" icon button in Phase 7) — not a WA space token, set explicitly via `min-width`/`min-height` per WCAG 2.5.5/5.5.

## Typography

Sizes and weights are drawn from Web Awesome's native `--wa-font-size-*` / `--wa-font-weight-*` scale (not reinvented), constrained to exactly 4 sizes and 2 weights at the page-content level.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--wa-font-size-m`) | 400 regular (`--wa-font-weight-normal`) | 1.6 (`--wa-line-height-normal`) |
| Label | 14px (`--wa-font-size-s`) | 600 bold (`--wa-font-weight-bold`) | 1.2 (`--wa-line-height-condensed`) |
| Heading | 20px (`--wa-font-size-l`) | 600 bold (`--wa-font-weight-bold`) | 1.2 (`--wa-line-height-condensed`) |
| Display | 32px (`--wa-font-size-2xl`) | 600 bold (`--wa-font-weight-bold`) | 1.2 (`--wa-line-height-condensed`) |

Notes:
- WA itself also defines `light(300)` and `semibold(500)` weights and uses `semibold` internally for some component chrome (e.g. form-control labels). That is WA's own component-internal styling and is **not** overridden — this contract only constrains page-content typography (the four roles above) to 400/600.
- Numeric content (table cells, chart tooltips, Kennzahlenband figures) additionally sets `font-variant-numeric: tabular-nums` so digits align in columns — apply this as a utility class/mixin, not per-component inline styles.
- German long compounds (`Verpflichtungsermächtigungen`, `Gewerbesteuerumlage`, …) must wrap at 360px: set `hyphens: auto` and `lang="de"` on `<html>`/`PageIntro` text blocks rather than relying on `overflow-wrap` alone.

## Color

Base palette = Web Awesome's default theme (dominant/secondary surfaces are already WA defaults, unchanged). The accent is a project-specific override: **"Ostbevern Gold"**, applying WA's built-in `.wa-brand-yellow` variant (gold is one of the two heraldic colors of the Ostbevern Wappen — gold field, red zigzag bars and beaver) instead of inventing a new, un-vetted hex ramp. Red (the Wappen's other heraldic color) is deliberately **not** used as the brand accent — see rationale below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--wa-color-surface-default`, WA default — unchanged) | Page background |
| Secondary (30%) | `#f1f2f3` (`--wa-color-surface-lowered` = `--wa-color-gray-95`, WA default — unchanged) | `ChartCard`/`wa-card` backgrounds, app-shell nav bar, table zebra striping |
| Accent (10%) | `#da7e00` loud fill / `#8c4602` text-on-white (`--wa-color-brand-60` / `--wa-color-brand-40` after applying `.wa-brand-yellow`) | Reserved for: primary buttons/links, active nav-item state, focus ring (`--wa-color-focus`, inherits `brand-60`), `BaseChart` primary/first-series accent, future "aktuelles Jahr" indicator (Phase 5 Jahr-Umschalter). **Never** used for body text decoration or as a general-purpose highlight. |
| Destructive | `#dc3146` (`--wa-color-danger`, WA default — unchanged) | Destructive confirmation UI only. **No destructive actions exist in this app's v1 scope** (static, read-only, no backend, no user data) — this row is a placeholder the contract keeps for completeness; nothing in Phase 1 renders it. |

Accent reserved for: primary CTA buttons, primary nav active-state, text links, focus-visible outline, the first/primary series color in `echartsTheme.ts`. Not for data semantics (see below).

**Contrast evidence (WCAG 2.1, computed against `#ffffff`):**
- Accent loud fill `#da7e00` → 3.01:1 (passes 3:1 non-text/UI-component minimum — used for focus rings and filled-button backgrounds with white icon/text at ≥ 24px or bold ≥ 19px per WCAG large-text allowance; body-size text must use the darker `#8c4602` variant instead).
- Accent text `#8c4602` → 7.02:1 (passes AA and AAA for normal text).
- Destructive `#dc3146` → 4.59:1 (passes AA for normal text).

**Why gold, not red, as the brand accent:** this app displays a structurally negative budget (2026 deficit −2.35 Mio. €, growing to −3.56 Mio. € by 2029) and will use red/green consistently as a **data semantic** for negative/positive figures from Phase 2 onward (deficits, decreases vs. increases). If the brand/CTA accent were also red, every primary button and active nav link would visually echo "this is bad," and red would stop being a reliable signal for negative numbers. Gold avoids that collision while still drawing on the Gemeinde's own heraldry.

**Data semantics (reserved separately from the UI color roles above — a `charts/format.ts`/`echartsTheme.ts` convention, not a button/link color):**
- Negative values, deficits, decreases → WA danger red tones (`--wa-color-danger-*`)
- Positive values, surpluses, increases → WA default success green tones (`--wa-color-success-*`, unchanged)
- These two must never be reused as arbitrary categorical chart colors or as interactive-element colors; they exist to be reused consistently once real figures start rendering (Phase 2+).

Dark mode: out of scope for Phase 1. WA ships a `.wa-dark` palette automatically keyed to `prefers-color-scheme`, but no toggle or dark-specific QA is built now — the app explicitly stays on the light theme (`color-scheme: light`) until a later phase decides to support dark mode. Flagged as an unresolved assumption, not a silent gap.
