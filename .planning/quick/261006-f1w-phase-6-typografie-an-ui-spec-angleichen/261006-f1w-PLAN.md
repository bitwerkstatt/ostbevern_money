<objective>
Fix the Typography BLOCKER from the Phase-6 UI review (`.planning/phases/06-kontext-seiten/06-UI-REVIEW.md`, Pillar 4). Six places in new Phase-6 code use the extra-large WA font-size token. The UI-SPEC (`06-UI-SPEC.md` §Typography) forbids that token. It allows exactly four sizes (Body m, Label s, Heading l, Display 2xl) and two weights (normal, bold).

All six affected selectors style section headings (`h2`). This was checked against the templates: EntwicklungPage `.om-entwicklung__abschnitt > h2`, InvestitionenPage `.om-investitionen__abschnitt h2`, RatEntscheidetPage `.om-rat-entscheidet__titel` (h2, template line 64), ZuschussListe `.om-zuschuesse__titel` (h2, line 166), UeberschussListe `.om-ueberschuss__titel` (h2, line 37) and NichtBeeinflussbarBlock `.om-nicht-beeinflussbar__titel` (h2, line 66). The spec maps `h2` to Heading, so every one becomes `--wa-font-size-l`. None of them is a key figure or Display, so `--wa-font-size-2xl` is not used. All six already declare `--wa-font-weight-bold` and `--wa-line-height-condensed`, the Heading weight and line height, and these stay.

A guard test in `stiltokens.test.ts` keeps the forbidden size and weight tokens out of exactly these six files. It follows the Fail-first style already used in that file.

Out of scope: the Phase-5 files (GlossarPage.vue, GlossarListe.vue, EinnahmenPage.vue:431) stay untouched, because the spec schedules their cleanup for Phase 7. Also out of scope are the other review findings, such as the h3 size in StellenplanPage.vue:246.

Purpose: Phase 6 ships with contract-compliant typography, and a CI test keeps it from regressing.
Output: six one-line CSS fixes and an extended `app/src/lib/__tests__/stiltokens.test.ts`.
</objective>
