Key facts (RESEARCH, verified in a scratch prototype):
- Web Awesome 3.14 `wa-drawer` restores focus to the element focused at open time with `setTimeout(() => trigger.focus())` right before dispatching `wa-after-hide` (`chunk.2UZFSBAI.js:107-111`); a synchronous focus in `beiAfterHide` is overwritten. Fix: queue `setTimeout(fokussiereUeberschrift)` from `beiAfterHide` when the link flag is set. Today even a normal navigation from the drawer leaves focus on the menu button (correction 1); the fix changes that case to the h1 too, which is what the router and UI-SPEC intend.
- vitest runs SSR without layout: `ueberlaeuft` is never true there, so overflow attributes are unit-tested through the pure helper and proven in the browser (Pitfall 2).
- Chromium's accessibility tree names both the region and the table (caption) after D-20; whether a screen reader announces the name twice is not testable here (assumption A1) and is a manual check at phase end.
- Do not gate on axe `landmark-unique`/`region` (best-practice rules; Web Awesome's own `wa-details` regions already violate them).
